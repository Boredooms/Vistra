# Agent Memory and Execution Traces

**Depends on:** [43](43-AGENT-RUNTIME-AND-ORCHESTRATION.md) · **Related:** [24](../04-backend-and-api/24-SESSION-AND-CONVERSATION-MANAGEMENT.md), [59](../10-applications-and-experience/59-VISTRA-STUDIO-ARCHITECTURE.md), [61](../10-applications-and-experience/61-ADMINISTRATION-AND-ANALYTICS.md)

## 1. Purpose

Define what the system remembers, where, for how long, and what it records about execution. Memory without
boundaries becomes a privacy liability; traces without structure become unusable logs.

## 2. Memory scopes

| Scope | Storage | Lifetime | Contents | Access |
|---|---|---|---|---|
| Turn | request | request | retrieved evidence, visual snapshot ref | run only |
| Conversation | `session_messages` + summary | retention (7–365 d) | messages, citations | session owner + org readers |
| End user (opt-in) | `application_sessions.end_user_meta` + `user_memories` | tenant policy | preferences, recurring facts the host explicitly allows | application |
| Organization | knowledge collections | until deleted | approved documents only | org |
| Run trace | `agent_runs`/steps | 90 d | execution record | `run.read` |

Rules: no memory is written without a scope owner; no cross-scope inference (session memory never becomes org
knowledge automatically); deleting a session deletes its memory.

## 3. Conversation memory

- Sliding window of the last N turns within a token budget (doc 24 §6).
- Older turns are replaced by a structured summary stored at `sessions.metadata.history_summary`:
  `{facts: [], open_questions: [], entities: [], updated_at}`.
- Summaries are generated by `text.fast`, validated against a schema, and capped (≤ 400 tokens).
- Summaries never include secrets, credentials, or content from redacted fields.

## 4. End-user memory (opt-in)

```json
{ "key": "preferred_currency", "value": "EUR", "source": "explicit_user_statement",
  "confidence": 0.9, "created_at": "…", "expires_at": "…" }
```

- Only written when the application enables `memory.enabled` and the host supplies an `end_user_ref`.
- Values are short, typed, and attributable to a message id.
- Used as context hints, never as authorization.
- User-visible and deletable ("forget this").

## 5. What is never stored as memory

- Passwords, tokens, card numbers, government ids.
- Content from `data-vistra-private` or masked fields.
- Inferred sensitive attributes (health, ethnicity, religion, politics, sexual orientation).
- Cross-tenant identifiers.
- Model "reasoning" or chain-of-thought.

## 6. Trace model

```json
{
  "run_id": "run_01H…",
  "org_id": "org_…", "application_id": "app_…", "session_id": "ses_…",
  "agent": { "id": "agt_…", "version": 4, "prompt_version_id": "pv_…" },
  "trigger": "sdk",
  "status": "completed",
  "intent": { "value": "knowledge_query", "confidence": 0.93 },
  "plan": { "steps": [ { "kind": "retrieval" }, { "kind": "respond" } ] },
  "steps": [
    { "index": 0, "kind": "retrieval", "status": "succeeded", "latency_ms": 214,
      "input": { "query": "starter plan limits", "collections": 2 },
      "output": { "candidates": 120, "returned": 6, "top_score": 0.87, "degraded": false } },
    { "index": 1, "kind": "respond", "status": "succeeded",
      "provider": "gemini", "model": "…", "tokens": { "in": 3120, "out": 180 },
      "citations": 2, "grounded": true, "latency_ms": 1620 }
  ],
  "usage": { "cost_micros": 1840, "fallback_used": false },
  "verification": null,
  "error": null
}
```

Stored across `agent_runs`, `agent_run_steps`, `tool_invocations`, `policy_decisions`, `approvals`,
`message_citations`. The API composes them into the trace view.

## 7. Trace content rules

| Include | Exclude |
|---|---|
| Intent, plan shape, step kinds | Full model prompts (unless debug capture) |
| Retrieval counts, top scores, chunk **ids** | Full chunk text in traces (available via citation) |
| Tool name, validated args (redacted) | Credentials, auth headers |
| Policy decision + reason code | Internal policy rule text beyond the reason |
| Approval actor and time | Approver's personal data beyond id |
| Provider, model, tokens, cost, latency | Raw provider payloads |

Debug capture (`TRACE_CAPTURE_PROMPTS=true`) is per-org, time-boxed (≤ 1 h), redacted, and audited.

## 8. Privacy of traces

- Traces are tenant data: deletable with the session/org.
- Cross-tenant support access is break-glass, audited, and read-only.
- No PII in `steps.output` beyond user-visible content; redaction applies to captured screenshots and form values.

## 9. Replay and debugging

- A completed run can be replayed against a **new** agent/prompt version without side effects (`dry_run`),
  to compare behavior.
- Replay never re-executes tools; tool steps are substituted with recorded results.
- Replay results are stored as `evaluation_results` linked to the source run.

## 10. Retention

| Data | Retention |
|---|---|
| Runs/steps/invocations | 90 d (tenant 30–365) |
| Traces referenced by an evaluation | 1 y |
| Audit events | 1 y+ (not tenant-deletable) |
| Debug captures | ≤ 7 d |
| End-user memory | until deleted or session retention expires |

## 11. Failure scenarios

| Scenario | Behavior |
|---|---|
| Step persistence fails | run fails before side effect (transaction) |
| Trace write for a completed run fails | retried; run result still returned; alert |
| Summary generation fails | fall back to truncation, flag `summary_degraded` |
| Memory contains stale preference | confidence + expiry; user can correct |
| Trace too large | steps capped, large outputs truncated with `truncated: true` |

## 12. Acceptance criteria

- [ ] Every run is reconstructable from persisted rows alone.
- [ ] No prompt or credential content in traces by default.
- [ ] Memory has an owner, a scope, and a deletion path.
- [ ] Replay cannot cause side effects.
- [ ] Studio shows the trace fields in §6 without server-log access.
